## 🟡スプレッドシート「利用者台帳」(1blasas…) のタイムゾーンが UTC−7（JSTでない）

      2026-07-30 実測。スクリプト側 appsscript.json は `Asia/Tokyo` だが、
      **保存先スプレッドシートの TZ 設定は UTC−7**。両者が別設定であることを見落とすと
      調査が16時間ずれる（実際に未実施報告ボタンの調査で2回つまずいた）。
      校正手順：自分でPOSTを1発打ち、HTTP応答ヘッダの Date と access_log の
      timestamp を突合する（`JST = セル値 + 16h`）。
      裏付け：同一10,054行を時刻帯ヒストグラムに落とすと、セル値では 01時=908件・
      06〜10時=0件（デイサービスとしてあり得ない）、+16hでは 09時=1550件ピークで
      07時立ち上がり・22時以降0件になる。
      影響範囲：Date型で書かれた全シートの日付列。access_log の全時刻。
      **是正は単独案件。60シート・利用者台帳を含み、設定変更で全シートの日付解釈が
      16時間動くため、影響棚卸しを先に行う。**
      当面の回避策：日付は必ず `Utilities.formatDate(..., 'Asia/Tokyo', ...)` の
      **文字列**で書く（Date型オブジェクトをセルに渡さない）。読み取りは純関数で正規化する
      （実装例：`gas/yawaragi-board/undone-report-core.js` の `undoneNormalizeDateCell_`）。
