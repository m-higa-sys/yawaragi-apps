## 3. Windows でやること（GAS）

1. `script.google.com` で**新規スタンドアロンプロジェクト**を作成（名前例: `kinmu-master-api`）
2. `gas/kinmu-master-api/コード.gs` の中身を貼り付けて保存
3. エディタで **`setupSheets()` を実行** → 承認 → 実行ログを見る
   - 「設定」シートが作られる
   - 「職員マスタ」にプルダウン・書式・`要確認` セルの黄色ハイライトが張られる
   - `KINMU_MASTER_TOKEN` が自動発行され、ログに出る（**この値を控える**）
4. **デプロイ → 新しいデプロイ → ウェブアプリ**
   - 次のユーザーとして実行: 自分
   - アクセスできるユーザー: 全員
5. `verify()` を実行して行数・列数・要確認件数をログで確認
6. 出てきた **デプロイID／ウェブアプリURL／token** をクロコに渡す
   → `gas/kinmu-master-api/.clasp.json`（sample をコピーして scriptId を記入）に反映する

### 呼び出し方

```
GET {webAppUrl}?token=XXXX                 … 全職員（退職者含む）
GET {webAppUrl}?token=XXXX&activeOnly=1    … 在籍者のみ
GET {webAppUrl}?token=XXXX&callback=cb     … JSONP
```

トークンはコードに直書きしていない（Script Properties）。CLAUDE.md の秘密情報ハードルール準拠。
**トークン未発行のうちは doGet が明示エラーを返して閉じる**（fail-closed）。職員の氏名・資格・入職日を
持つAPIなので、設定漏れで丸見えになる状態を作らないための作りにしてある。

## 5. 判断したこと（指示書から外れた点・先に出す）

1. **シートは xlsx アップロードではなく CSV 取込で作った。**
   Mac から Google Sheets へ直接書き込むAPIが無く、xlsx のバイナリアップロードは Drive 側に弾かれた。
   CSV 取込はタブが1枚しか作れず入力規則も持てないので、**「設定」シートと入力規則は GAS の
   `setupSheets()` が作る**構成にした。結果、シートが完成形になるのは §3 の手順3を実行した後になる。

2. **プルダウン列には「要確認」を書かず、空欄にした。**
   指示は「職種はプルダウン固定（6職種）」と「不明値は要確認と入れる」の両方。両立しないので、
   自由入力列（カナ・入職日・退職日・資格・役割）には `要確認` を入れ、プルダウン列（職種・区分）は
   **空欄＋備考に理由**とした。プルダウンに `要確認` を足せば統一できるが、6職種固定を崩すので採らなかった。
   APIの `要確認` 配列は両方を拾うので、機械的な扱いは変わらない。

3. **「既存の一次データに明記がある値」は入れた。** 出典コードを備考列に必ず書いてある。
   - `[確定]` 指示書の確定済みの値
   - `[JSON]` 中島さん版 2026.02月用.json / 2025.11.json
   - `[SC:行番号]` shift-create.html
   - `[ケアズ]` ケアズ日別CSV.csv の「ふりがな」列
   - `[契約]` Drive の雇用契約書原本
   パターンからの推測（例: 他の人がCだからこの人もC）は**一切していない**。

4. **単一職種の行の比率①には 100 を入れた。** 職種が1つだけなら100%は推測ではなく算術上の帰結のため。
   職種②が後から足されたら要修正。

5. **星野さんの入職日に `2026-02-13` を入れた。** これは**再入社日**（[契約] memory `雇用契約_満了日正本_2026-08`）。
   初回入職日は別。備考に明記してあるが、バックログの起算に使ってよいかは要判断。

6. **読み取りAPIにトークン認証を付けた。** 指示に認証の指定は無かったが、氏名・資格・入職日を返す
   ウェブアプリを `ANYONE_ANONYMOUS` で公開することになるため。CLAUDE.md の「全アプリに共有トークン認証」にも合わせた。
