### 保有資格のスキーマ変更（2026-08-05）

`資格名:取得日` をカンマ区切り。取得日が分からないものは `資格名:要確認`。

```
比嘉学     = 柔道整復師:要確認,介護福祉士:2026-03-26
髙山奈緒美 = 看護師:要確認
小野重次郎 = 要確認            ← 資格名そのものが未確定
```

APIは `[{ name, acquiredOn }]` で返す。`acquiredOn` は取得日が読めないとき空文字。

| セルの値 | APIの返り | 要確認 |
|---|---|---|
| `柔道整復師:要確認,介護福祉士:2026-03-26` | `[{柔道整復師,''},{介護福祉士,'2026-03-26'}]` | `資格取得日` |
| `看護師:2020-04-01` | `[{看護師,'2020-04-01'}]` | なし |
| `介護福祉士`（旧形式） | `[{介護福祉士,''}]` | `資格取得日` |
| `要確認` | `[]` | `保有資格` |

## 4. ★第2弾への申し送り（計算エンジン実装時に必ず読む）

1. **資格判定は「対象月時点で取得日を過ぎているか」で行う。**
   マスタの現在値を全期間に適用してはならない（バックログが過大になる）。
   例: 比嘉さんの介護福祉士は 2026-03-26 取得。2026-02月分の計算で介護福祉士として数えてはいけない。
   → APIの `保有資格[].acquiredOn` を使う。

2. **在籍判定も「対象月に在籍していたか」で行う。**
   `入職日 <= 対象月末` かつ（`退職日` が空 または `退職日 >= 対象月初`）。
   `activeOnly=1` は「今日の在籍者」であって過去月の在籍者ではない。バックログでは使わない。

3. **比嘉さんは介護福祉士保有のため、介護職員に振れる日は
   サ体加算の分子・分母の両方にカウントする。分母のみは誤り。**

4. **資格判定は職種名ではなく「保有資格に介護福祉士を含むか」で行う。**
   比嘉さんの職種①は `管理者` だが介護福祉士を保有している。職種名で判定すると取りこぼす。

5. **勝又・星野の日次ルール**（タグ `相談員条件`）
   下浦・喜多のいずれかが出勤 → **介護職員**／両名不在 → **生活相談員**。
   マスタは職種①②とタグだけを持つ。日ごとの選択と比率はエンジン側で決める。
   （このためマスタの比率①②は空欄で正常。要確認には数えない）

6. **分母は用途別に使い分ける。** 一覧表＝`常勤所定_週時間_一覧表用`（40h/週）、
   加算判定＝`常勤所定_月時間_加算判定用`（暫定160h/月）。`settingsMeta[].状態` が `暫定` の間は
   算出結果にも暫定である旨を出す。

## 6. 判断したこと（指示から外した点・先に出す）

1. **列追加は setupSheets() 拡張**（§1参照）。CSV再生成はシートIDが変わるため採らなかった。
2. **比率の要確認免除は「職種が日ごとに切り替わるタグ」だけに限定した。**
   タグを持つ行を一律に免除すると、比嘉さんの `看護2名条件` まで免除されて
   **管理者と機能訓練指導員の配分（比率①）が隠れる**。免除対象は定数
   `TAGS_SWITCHING_SHOKUSHU = ['相談員条件']` に明示し、テストで固定した。
3. **退職者3名の職種を [JSON 2026.02] から投入した。** 判断3の「田中・伊得の3職種はこれで収容」に従い、
   同じ出典の石丸さん（生活相談員）も揃えた。備考に出典を明記してある。
4. **プルダウン列には「要確認」を書かず空欄のまま。**（前回からの継続。6職種固定を崩さないため）
5. **条件付き書式を「完全一致」から「部分一致」に変えた。** `介護福祉士:要確認` のような
   複合値でもハイライトされるようにするため。
