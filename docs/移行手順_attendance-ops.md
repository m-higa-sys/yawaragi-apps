## 0. 編集権限の扱い（決定済み・実装済み）

### 何が問題だったか

旧アプリの31行目には、こういう1行がありました。

```js
const IS_READONLY = location.hostname.includes('github.io');
```

意味は「**アドレスが github.io なら閲覧専用にする**」です。これは
**「公開先に出たら誰にも編集させない」ための安全装置**であって、バグではありません。
ファイルを開いて使う分（file://）には効かないので、今まで問題になりませんでした。

ただしこのまま Pages に置くと、社長も編集できなくなり業務が止まります。

| | file://（今） | github.io（何もしない場合） |
|---|---|---|
| 出勤表の編集 | できる | **できない** |
| 保存（autoSave） | 動く | **動かない** |
| データの読み先 | この端末の localStorage | GASから取ってきたメモリ上のデータ |
| **書出したデータを復元しても** | 反映される | **画面に出ません**（読み先が違うため） |

### 決定：案2（鍵方式）を採用 — 実装済み

安全装置を**外すのではなく**、`admin.html` と同じ鍵（adminKey）方式に**置き換え**ました。
**鍵を持つ端末だけが編集でき、鍵が無ければ閲覧専用**になります。

| 案 | 内容 | 判断 |
|---|---|---|
| 案1 | 判定をやめて Pages でも常に編集可にする | ❌ 不採用。URLを知っていれば誰でも編集できてしまう |
| **案2** | **`admin.html` と同じ鍵方式。鍵を入れた端末だけ編集可** | ✅ **採用** |
| 案3 | 編集用と閲覧用でファイルを2本に分ける | ❌ 不採用。同じコードを2箇所メンテすることになる |

**採用の理由**: リポジトリの決まり（CLAUDE.md）に「全アプリに共有トークン認証あり。新規アプリも同じ方式に揃える」とあり、
`admin.html` に鍵を localStorage に保存する実装がすでにあります（[admin.html:128-193](../admin.html#L128-L193)）。
**同じキー名・同じ保存先をそのまま使う**ので、新しい仕組みを増やしていません。

### 実装で守った4つの条件

**① フェイルセーフ（どう転んでも編集可にならない）**
次の4つは**すべて閲覧専用**に倒れます。テストで固定済みです。

| 状況 | 結果 |
|---|---|
| 鍵が無い | 閲覧専用 |
| localStorage が読めない（プライベートモード等で例外） | 閲覧専用 |
| 鍵はあるが空白だけ（形式が不正） | 閲覧専用 |
| 鍵が文字列でない／判定中に例外 | 閲覧専用 |

**② 閲覧専用だと画面で分かる**
- 画面上部に **「出勤＆送迎表（閲覧専用モード｜編集・保存できません）」** が常時出ます
- その横に **「🔑 編集するには鍵が必要です」** のリンク（`admin.html` へ）
- 何か編集して保存されるはずのタイミングで、**「閲覧専用のため保存されませんでした（編集するには鍵が必要です）」**と画面下に出ます（黙って消えません）
- **鍵があるときは、この行は出ません**（普段の画面に余計な行は増えません）

**③ 既存の分岐は1つも消していない**
閲覧専用の挙動を決めている28箇所には**一切手を入れていません**。差し替えたのは
`IS_READONLY` を決める**代入の1行だけ**です（削除された参照は0件）。

**④ 鍵の値はどこにも書いていない**
コード・テスト・この手順書・報告のいずれにも鍵の値は載せていません。
鍵は社長の端末のブラウザの中だけにあります。

### ⚠️ この鍵の限界（必ず理解しておいてください）

**これはクライアント側（ブラウザ側）の入口ゲートです。サーバ側の認証ではありません。**

- **防げること**: うっかり編集、第三者がURLを開いて偶発的に操作してしまうこと
- **防げないこと**: GAS（サーバ）へ直接データを送りつける行為。
  GAS は現在 `ANYONE_ANONYMOUS`（誰でも匿名でアクセス可）のままです
- **サーバ側の認証は別課題**です（既存の宿題として残っています）

つまり「鍵を入れたから安全」ではなく、**「うっかりを防ぐ蓋」**として理解してください。

## 3. 時給の受け渡し（金額をどこにも残さない経路）

### 考え方

- 旧アプリの実効時給 ＝ **HTML内の既定値** に **localStorage の上書き分** をかぶせたもの
- 新アプリは既定値が空なので、**合成した結果**を渡す必要がある
- 通り道は **社長の画面とクリップボードだけ**。ファイル・チャット・報告書には出さない

### 手順（2手で完結）

**ステップA — 貼り先: 旧アプリ（file://）の Console**

```js
copy(JSON.stringify(Object.assign({}, DEFAULT_WAGES, JSON.parse(localStorage.getItem('yawaragi_staff_wages') || '{}'))));
console.log('コピーしました（人数: ' + Object.keys(Object.assign({}, DEFAULT_WAGES, JSON.parse(localStorage.getItem('yawaragi_staff_wages') || '{}'))).length + '名）');
```

- `copy(...)` はブラウザの開発者ツールに元からある命令で、**中身を画面に出さずクリップボードに入れます**
- Console に出るのは **人数だけ**

**ステップB — 貼り先: 新アプリ（github.io）の Console**

```js
navigator.clipboard.readText().then(t => {
  const o = JSON.parse(t);
  localStorage.setItem('yawaragi_staff_wages', JSON.stringify(o));
  console.log('時給を設定しました（人数: ' + Object.keys(o).length + '名）');
}).catch(e => console.log('クリップボードから読めませんでした: ' + e.message));
```

- Console に出るのは **人数だけ**
- 読めなかった場合の代替は下の「うまくいかないとき」を参照

### うまくいかないとき

`navigator.clipboard.readText()` はブラウザが許可を求めることがあります（**要検証**・第7章に記載）。
読めない場合は、次のどちらかにします。

- **代替1**: `localStorage.setItem('yawaragi_staff_wages', ` と打ってから **Ctrl+V で貼り付け**、`)` を足して実行
  （貼り付けた瞬間に Console に金額が見えますが、**社長の画面の中だけ**です）
- **代替2**: 新アプリの人件費パネルの「単価」欄に、手で入力する（13名分）

> 失敗したら戻す方法: `localStorage.removeItem('yawaragi_staff_wages')` → 再読み込みで、未設定に戻ります。

### ステップ8 — 残りのデータを移す（標準配置・測定管理・平均単価・印刷レイアウト）

**貼り先: 新アプリの Console**。バックアップ②のダンプファイルを使います。

1. ダンプファイルをテキストエディタで開き、**全文をコピー**
2. Console で次を実行し、`貼り付け` の位置にペースト

```js
(() => {
  const src = JSON.parse(`貼り付け`);
  const targets = ['yawaragi_standard_positions', 'yawaragi_measurement_tracking', 'yawaragi_avg_revenue', 'yawaragi_print_layout'];
  let n = 0;
  targets.forEach(k => { if (src[k] !== undefined) { localStorage.setItem(k, src[k]); n++; } });
  console.log('移した設定: ' + n + '件');
})()
```

> 失敗したら戻す方法: これらは設定データなので、消しても業務データは失われません。
> `targets` の各キーを `removeItem` すれば初期状態に戻り、画面から再設定できます。
